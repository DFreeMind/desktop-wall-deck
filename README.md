# 桌面壁纸

Windows 多显示器壁纸管理工具。可以按显示器分别设置壁纸，也可以一键全部统一，或把一张图跨屏拼接铺满。内置本地壁纸库，支持导入与整理。

## 为什么需要它

Windows 自带的「个性化 → 背景」在多显示器场景下有三个明显短板：

1. 只能给所有屏幕设置同一张图，无法分别指定
2. 无法预览「哪张图配哪块屏」——设完切回桌面才发现构图被裁掉了
3. 换端口、拔插显示器后，配置容易错乱

本项目针对这三点设计：按物理排列绘制显示器布局，拖拽即设置；设置前提示裁切比例；用显示器硬件身份记住每块屏的壁纸，插拔后自动恢复。

## 功能

- **显示器拓扑画布**：按系统真实排列等比绘制，竖屏不会被压扁；未分配壁纸的屏幕以斜纹占位并标注「未设置」，一眼看出哪块屏还没配
- **三种投放方式**：全部统一 / 仅选中屏幕 / 跨屏拼接
- **本地壁纸库**：导入时自动转码（含 EXIF 方向校正）、生成缩略图、去重
- **多级合集**：新建/重命名/删除文件夹，按合集筛选；点开父合集会**穿透**列出所有子文件夹内的壁纸，删除合集时壁纸上移而非连带删除
- **比例提示**：竖屏配横图时提前说明会裁掉多少
- **壁纸来源**：内置 Unsplash、Wallhaven、维基共享资源等 6 个知名开源壁纸站入口，点开跳到系统浏览器
- **热插拔恢复**：显示器重新接入后按身份自动恢复壁纸
- **虚拟屏折叠**：自动识别模拟器、串流工具的虚拟显示器并默认隐藏

## 界面结构

三栏布局：左侧 196px 导航（显示器 / 壁纸库 / 未归类 + 合集成树 + 壁纸来源 / 设置），中间内容区，右侧 288px 属性面板（预览、投放目标、填充方式、屏幕状态清单）。

## 技术栈

| 层 | 选型 |
|---|---|
| 桌面外壳 | Tauri 2 |
| 系统调用 | Rust + `windows` crate，直连 COM `IDesktopWallpaper` |
| 前端 | React 18 + TypeScript + Vite |
| 持久化 | SQLite（rusqlite，bundled） |
| 图像处理 | `image` + `kamadak-exif` |

## 开发

需要 Rust 1.77+、Node 18+、Windows 10/11。

```bash
npm install
npm run tauri dev
```

首次启动会下载并编译 Rust 依赖，耗时约数分钟。

## 构建

```bash
npm run tauri build
```

产物：

- 可执行文件 `src-tauri/target/release/desktop-wall-deck.exe`（约 9.5MB，可直接运行）
- 安装包 `src-tauri/target/release/bundle/nsis/桌面壁纸_0.1.0_x64-setup.exe`（约 2.7MB）

首次打包需要联网下载 NSIS 工具链，若网络不稳定会报 TLS 或 `peer closed connection`。
可重试，或先用 `npx tauri build --no-bundle` 只产出 exe。

## 测试

```bash
cargo test --manifest-path src-tauri/Cargo.toml --lib   # 单元测试，无副作用
cargo test --manifest-path src-tauri/Cargo.toml          # 含端到端测试
```

注意 `tests/e2e_apply.rs` 会**真实修改桌面壁纸**（结束时自动恢复），在他人机器上运行前请留意。

## 数据位置

壁纸副本、缩略图与数据库存放在 `%APPDATA%/com.duqimeng.desktopwalldeck`：

- `library.db`：SQLite 数据库（壁纸元数据 + 显示器绑定 + 合集树）
- `files/`：规范化后的壁纸副本（JPEG 质量 92，带透明通道的保留 PNG）
- `thumbs/`：缩略图缓存
- `span/`：跨屏拼接的临时分片

删除应用后该目录仍然保留，重新安装即可恢复壁纸库。

## 设计取舍记录

**为什么用显示器布局画布，而不是「显示器 1 / 2 / 3」列表**

多屏用户的屏幕尺寸与位置差异很大（例如 3072×1920 主屏 + 竖屏 + 1080p 副屏），编号无法建立直观对应。按真实坐标绘制后，用户点哪块就是哪块，与系统显示设置一致。

**为什么壁纸入库要复制而不是引用原路径**

用户清理下载目录是常态。若直接引用原文件，壁纸会突然变黑。复制一份进库目录后，原始素材随便删。

**为什么跨屏拼接要在本地切图，而不用 `SetPosition(SPAN)`**

`SPAN` 只在所有显示器构成连续矩形时正确。副屏纵向偏移几乎不可避免，`SPAN` 会把这些空隙填成背景色。本地按各屏矩形裁切后分别投放，才能真正「铺满」。

**为什么持久化的是 EDID 逻辑身份而非设备路径**

设备路径含端口编号，换 HDMI 口就会变。身份由「厂商码 + 型号 + UID」组成，换口后仍能认出是同一台显示器。

**为什么删文件夹时壁纸上移，而不是一起删掉**

合集只是分类标签，不是容器。用户删掉「临时」这个概念，不等于要销毁里面 30 张图。所以删除时把壁纸挂到父级（顶级则回到「未归类」），子文件夹也上移一级，只删文件夹这一行。

**为什么壁纸来源只做外链，不做抓取**

抓取涉及各家授权条款差异（Unsplash 要带 UTM 与 hotlink、Wallhaven 限制批量下载），维护成本远高于收益，且一旦站点改版就会失效。外链把选图这件事交给更专业的人做，本应用只负责「设到哪块屏」。

## 已知限制

- 仅支持 Windows 8 及以上
- 不支持动态壁纸（视频、HTML），需要注入宿主进程，不在当前范围
- 不抓取在线壁纸，只提供站点跳转入口
- 若壁纸被其他工具（如系统设置）改动，本应用不会反向同步，刷新后以系统现状为准
